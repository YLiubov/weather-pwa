# Vejr PWA: подготовка к презентации

Приложение погоды: Open-Meteo API, Vanilla JS, ES Modules, MVC, Atomic Design, адаптивный CSS.
Дальше описано, что сделано и зачем, начиная с модели и компонентов.

---

## 1. Архитектура MVC

| Слой | Папка / файл | Отвечает за |
|---|---|---|
| **Model** | `src/models/weatherModel.js` | Получает данные от API и преобразует их. Никакого DOM. |
| **View** | `src/views/weatherView.js` | Рисует HTML на странице и ловит клики. Данные не грузит. |
| **Controller** | `src/controllers/weatherController.js` | Связывает Model и View, хранит состояние (`state`). |

**Как идут данные:** `main.js` вызывает `init()`, контроллер просит модель получить данные, затем отдаёт их View, View рисует.

### Model: функции
- `getLocation()` — координаты через `navigator.geolocation` (Promise). Если отказали или нет ответа 5 секунд, берётся København. Координаты округляются до 2 знаков, чтобы адреса запросов повторялись и кэш работал офлайн.
- `fetchForecast(location)` — запрос к Open-Meteo: `current`, `daily`, `hourly`, 7 дней, ветер в м/с, `timezone=auto`.
- `getCityName(location)` — название города по координатам (BigDataCloud), запасной вариант «Din position».
- `describeWeather(code, isDay)` — WMO-код погоды в название (датское) и имя иконки. Ночью выбирает луну.
- `windDirection(deg)` — градусы в сторону света (N, NØ, Ø, SØ, S, SV, V, NV).
- `toCurrent / toDays / toHours` — превращают «колонки» API (массивы) в удобные массивы объектов. Это и есть слой трансформации данных.

### Controller
- `state` — единое хранилище: `current`, `days`, `hours`, `selectedDate`, `city`, `tab`.
- `getTheme(hour)` — тема по времени суток (утро 5-11, день 11-17, вечер 17-22, ночь).
- `show()` — выбирает день, фильтрует его часы, ставит `data-theme` на body и вызывает View.
- `init()` — загрузка, подписка на клики, `try/catch` для ошибок.

### View
- `renderLoading / renderError / renderWeather` — рисуют состояния.
- `bindEvents` — **делегирование событий**: один слушатель на `#app`, потому что карточки пересоздаются при каждом рендере. `closest()` находит нужную карточку, `dataset` читает `data-date` и `data-tab`.

## 2. Atomic Design

Каждый компонент — функция, которая возвращает строку HTML. У каждого своя папка с `.js` и `.css`; CSS подключается строкой `import './X.css'` (Vite сам собирает).

```
src/components/
  atoms/       WeatherIcon  UiIcon  Temperature
  molecules/   WindInfo  DayCard  HourCard  StatsBar  Tabs
  organisms/   Header  DayList  DayDetail
```

- **Атомы** — мельчайшие, независимые элементы. `WeatherIcon` и `UiIcon` рисуют иконку как CSS-маску (форма из PNG, цвет из переменной `--icon`, поэтому она меняет цвет в каждой теме). `Temperature` — число с градусом.
- **Молекулы** — несколько атомов вместе. `DayCard` (строка дня), `HourCard` (карточка часа), `WindInfo` (иконка ветра + скорость + направление), `StatsBar` (feels like / humidity / wind), `Tabs` (переключатель I dag / 7 dage).
- **Организмы** — крупные блоки страницы. `Header` (город, температура, иконка, холмы), `DayList` (список 7 дней), `DayDetail` (вид одного дня: 8 карточек каждые 3 часа).

**Правило зависимостей:** атом ничего не знает о других; молекула использует атомы; организм использует молекулы и атомы.

## 3. Дизайн (по макету из PDF)

- **4 темы по времени суток** через CSS-переменные и `body[data-theme="..."]`: `--bg` (градиент), `--text`, `--muted`, `--icon`, `--glass`, `--glass-border`, `--badge`, `--hill-1/2/3`. Компоненты используют только переменные, поэтому смена темы меняет всё сама.
- **Градиенты:** вертикальный градиент неба + радиальное свечение из правого верхнего угла; у плашки с временем суток свой градиент.
- **Glass-эффект:** полупрозрачный фон + рамка 1px + `backdrop-filter: blur(22px)`.
- **Шрифты:** Noto Serif JP (цифры, заголовки) и Zen Kaku Gothic New (подписи). Установлены через `@fontsource`, поэтому работают офлайн.
- **Холмы:** SVG из трёх слоёв с `preserveAspectRatio="none"`, цвет из переменных темы.
- **Спецификация:** отступы 20px, радиусы 18/24/999px, главная иконка 90x90, температура 96px / 300.

## 4. Адаптивность

- Mobile-first: базовые стили для телефона, `@media (min-width: 768px)` для планшета и десктопа.
- `#app` ограничен по ширине и центрирован.
- Сетки: `grid` для часов (2 колонки, `minmax(0, 1fr)`, чтобы не вылезали), строка дня `grid` с фиксированными колонками.

## 5. Данные из задания (где что выводится)

## 7. Вопросы, которые могут задать

- **Почему `async/await` и Promise?** API и геолокация асинхронные; обёртка над `getCurrentPosition` в Promise позволяет писать `await`.
- **Зачем делегирование событий?** Карточки создаются заново при каждом `innerHTML`; один слушатель на родителе живёт всегда.
- **Почему округляем координаты?** Чтобы URL запроса повторялся и Service Worker находил его в кэше.
- **Чем MVC отличается от Atomic?** MVC делит логику приложения (данные / вид / управление), Atomic делит сам интерфейс на уровни компонентов.
- **Как работает смена темы?** Контроллер ставит `data-theme`, CSS-переменные переопределяются для этого значения.
- **Что при ошибке сети?** `try/catch` в `init()` показывает сообщение (с Service Worker будет брать последние данные из кэша).
